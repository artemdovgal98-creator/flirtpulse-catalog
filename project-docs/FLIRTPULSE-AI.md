# FlirtPulse — implementation notes

Catalog of dating, webcam, live-cam and everyday services, built on Next.js + Totalum.
The public interface describes everything purely as **services and platforms** — no partner
programmes, networks, payouts or pricing models appear anywhere a visitor can reach.

## Pages

| Route | What it does |
|---|---|
| `/` | Entry screen: hero, live stats, 4 category shortcuts, top-6 services, 18+ notice |
| `/catalog` | Core catalog — search, category + country filters, sorting, infinite scroll |
| `/ai-chat` | AI assistant grounded on the real catalog, answers in the user's language |
| `/favorites` | Saved services with the empty state + "Открыть каталог" CTA |
| `/profile` | Account + **admin dashboard** for administrators (see below) |
| `/go/[id]` | Hidden tracking redirect — records the click, then 302s to the real destination |
| `/privacy-policy`, `/terms-of-service`, `/about`, `/cookie-policy`, `/contacts` | Legal / info pages |
| `/login`, `/register` | Better Auth email + password |

All of them are public (guests can browse) — see `publicRoutes` in `src/middleware.ts`.

## Database (Totalum)

| Table | Purpose | Relations |
|---|---|---|
| `user`, `session`, `account`, `verification` | Better Auth | `session.user_id`, `account.user_id` → `user` (manyToOne) |
| `admin_user` | **Grants admin access** — one row per administrator | `user` → `user` (manyToOne) |
| `offer` | 264 catalog cards | — |
| `favorite` | Saved services | `user` → `user`, `offer` → `offer` (manyToOne) |
| `user_preference` | Language + favourite categories | `user` → `user` (manyToOne) |
| `chat_message` | AI conversation history | `user` → `user` (manyToOne) |
| `click` | One row per outbound click | `offer` → `offer`, `user` → `user` (manyToOne) |
| `visitor_session` | Presence heartbeat, used for "online now" | `user` → `user` (manyToOne) |

`offer` fields: `name, slug, description, category[], geo[], tags, quality_score, image_url,
images[] (file, multiple), launch_date, is_featured, is_custom, click_count, status` — plus the
**server-only** `network` and `offer_url`.

### Why admin access is not a `user.role` field

The Totalum auth `user` table rejects duplicate values on custom columns, so a `role` column with
a `"user"` default would make the **second** registration fail. Admin membership therefore lives in
the separate `admin_user` table. To grant access, add a row with the user's `_id` and email
(Totalum back office → Administrators); to revoke it, delete the row.

## Interface cleanliness (requirement 3)

This is enforced **server-side**, not by hiding fields in the UI:

- `PRIVATE_OFFER_FIELDS` in `src/lib/catalog.ts` lists everything that must never leave the server
  (`offer_url, network, payout_model, payout_amount, payout_label, epc, conversion_flow`).
- `/api/offers` and `/api/ai/chat` pass those fields to Totalum's `_omit` **and** delete them from
  the response objects before serialising. Two independent layers.
- `src/data/offers.ts` runs `cleanTags()` over every row, dropping `pps / soi / doi / revshare /
  multicpa / network / smartlink / traffic / epc` tags and renaming `nogeo → worldwide`,
  `vitrine → regional`.
- Descriptions are generated by `describe()` as plain service copy in Russian.
- The AI system prompt explicitly forbids mentioning partner programmes, commissions or payouts.

## Hidden tracking links (requirement 4)

Cards never contain the destination URL. `OfferCard` links to
`/go/{id}?v={visitorId}&lang={lang}`; the route handler (`src/app/go/[id]/route.ts`):

1. loads the offer server-side,
2. writes a `click` row (offer, user or visitor id, IP, UA, referrer, language),
3. increments `offer.click_count`,
4. 302-redirects to `offer.offer_url`.

Analytics failures are logged but never block the redirect.

## Admin dashboard (requirement 1)

`/profile` renders `AdminStats` + `ShowcaseManager` when `/api/admin/me` reports `isAdmin: true`.
Hiding the UI is presentation only — **every** admin route re-checks `getAdminGuard()` server-side
and returns `403` otherwise.

| Metric | Source |
|---|---|
| Total users | `count(user)` |
| New users (7 days) | `count(user, createdAt >= now-7d)` |
| Total / today / 7-day clicks | `count(click)` with `clicked_at` ranges (UTC day boundary) |
| Online now | `count(visitor_session, last_seen_at >= now-5min)` |
| Showcases | `count(offer, status=active)`, plus custom count |
| 7-day histogram, top cards, latest clicks | derived in `/api/admin/stats` |

`PresenceTracker` (mounted in `AppProviders`) pings `/api/track/heartbeat` every 30 s with a stable
random visitor id from `localStorage` (`src/lib/visitor.ts`). The stats panel auto-refreshes every 15 s.

## Showcase CRUD + media (requirement 4)

`ShowcaseManager` (`src/components/admin/ShowcaseManager.tsx`) supports unlimited custom cards:

- title, description, categories (multi), countries (multi), tags, visible/hidden, featured
- **up to 3 images, 10 MB each** — validated in the browser *and* again in
  `/api/admin/upload` (size, count and MIME type) before `totalumSdk.files.uploadFile`
- the hidden tracking link, stored in `offer.offer_url`

| Route | Method | Notes |
|---|---|---|
| `/api/admin/me` | GET | `{ isAdmin, email }` |
| `/api/admin/stats` | GET | Dashboard metrics |
| `/api/admin/showcases` | GET / POST | List (with tracking links) / create |
| `/api/admin/showcases/[id]` | PUT / DELETE | Update / delete |
| `/api/admin/upload` | POST | Multipart, ≤3 files, ≤10 MB each |

Validation lives in `src/lib/showcase.ts` — **not** in the route files, because Next.js rejects
non-route exports from `route.ts`.

## Catalog dataset

`src/data/offers.ts` holds the whole catalog as compact rows:

- `CRAKREVENUE_ROWS` — 106 flagship services
- `PARTNER_ROWS` — 60 additional services
- `VITRINE_BASES` × `GEO_PACKS` — 64 regional editions of the strongest brands
- `USEFUL_ROWS` — **34 "Полезное" services** (VPN, password managers, photo/AI tools, translation,
  gifts, travel, health, style…), each with hand-written Russian copy

**Total: 264 cards.**

> ⚠️ The "Полезное" list was written from scratch: the request referenced uploaded service items,
> but no files were attached to the prompt. Replace `USEFUL_ROWS` with the real list and re-run the
> seed when the file is available.

### Adding more cards

1. Append rows to the arrays in `src/data/offers.ts`.
2. `POST /api/offers/seed` — **upserts by slug**: existing rows are rewritten with the current copy,
   new rows created, and seeded rows whose slug disappeared are deleted (`?purge=0` to keep them).
   Cards created by the admin (`is_custom: "yes"`) are never touched.

## API routes

| Route | Method | Notes |
|---|---|---|
| `/api/offers` | GET | `q, categories, geos, ids, sort, offset, limit` → `{ items, total, hasMore }`; private fields stripped |
| `/api/offers/seed` | POST | Upsert-by-slug seeding |
| `/api/favorites` | GET / POST | Toggle by `offer_id`; guests fall back to localStorage |
| `/api/preferences` | GET / PUT | Language + favourite categories |
| `/api/ai/chat` | POST | Detects country/category from free text in 12 languages, answers with `totalumSdk.openai` (`gpt-4.1-mini`) |
| `/api/track/heartbeat` | POST | Presence ping |
| `/api/admin/*` | — | See the table above |

All routes return `{ ok: true, data }` and are called from the client through `src/lib/api.ts`
(`api.get/post/put/delete/upload`).

## Sorting

`relevance` (quality score), `newest` (launch date), `name` (A-Z) and `popular`
(`click_count desc`) — the payout-model sort was removed.

## Design

Dark indigo/violet night theme defined in `src/app/globals.css` (`.dark`, `fp-card`, `fp-glass`,
`fp-heart`, `fp-sheen`, `fp-grain`). Display font **Unbounded**, body font **Manrope** — both with
Cyrillic subsets. Fixed bottom navigation + sticky top header live in `src/components/AppShell.tsx`.

## Languages

12 locales in `src/lib/i18n.tsx` (en, uk, ru, pl, de, fr, es, pt, it, tr, ar, zh) with instant
switching, `localStorage` persistence, automatic RTL for Arabic, and a best-effort sync to
`user_preference` for signed-in users. Default locale: Russian. Visitor-facing strings are
translated in all 12 languages; the admin-only strings are Russian + English and fall back to
English elsewhere.
